# portal-web: Work Card portal and validation workspace

One Angular application for both officer surfaces (AMC-LLD-01, chapter "Portal Build (Angular)").
All data comes from the Platform API in `../backend`.

| Concern      | Choice                                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------------------------- |
| Framework    | Angular 21, standalone components, signals, zoneless, strict TypeScript                                               |
| UI           | Angular Material + CDK, Intertec palette (`src/app/shared/theme/_theme.scss`), Carlito and Material Icons self-hosted |
| Grid         | AG Grid Enterprise 36 (`src/app/shared/grid/ag-grid.setup.ts`), registered lazily on the statement route              |
| Auth         | `@azure/msal-angular` 6: Entra ID, auth code + PKCE, redirect flow, session storage                                   |
| State        | NgRx SignalStore                                                                                                      |
| API client   | Generated by ng-openapi-gen from `openapi/openapi.json` into `src/app/core/api/generated`                             |
| Live updates | SSE (`core/sse/event-stream.service.ts`), ticket exchange, 1–30 s back-off                                            |
| Quality      | angular-eslint, Prettier, Vitest                                                                                      |

Angular 22 needs Node ≥ 22.22.3. This workspace uses Angular 21 (LTS) to run on Node 22.21. Upgrade
with `ng update @angular/core@22 @angular/cli@22` after the Node upgrade.

## Run locally

```bash
npx -y npm@11 install   # npm 10.9 fails on this tree ("reading 'edgesOut'"); npm 11 works
npm start               # http://localhost:4200, demo data from the in-browser mock
npm run start:api       # http://localhost:4200, real data from the backend on 127.0.0.1:8000
```

Before sign-in works, put the `amc-portal-spa` client ID and the tenant ID into
`public/assets/config.json`. Add `http://localhost:4200/auth/callback` (after sign-in) and
`http://localhost:4200/logout` (after sign-out) as SPA redirect URIs on that app registration (DEV
only). Each environment registers the same two paths on its own host.

### Against the local backend (`npm run start:api`)

Start the backend first (`../dev/README.md`: Docker, then `python -m app` in `../backend`). The
`api` configuration (angular.json) builds with `mockApi: false`, and `proxy.conf.json` forwards
`/api` to `http://127.0.0.1:8000` without the `/api` prefix.

Sign-in mode is then `local`: **Sign in** lists the backend's sample officers
(`GET /v1/dev/users`), and picking one asks the backend for a token (`POST /v1/dev/sign-in`). The
backend serves those two routes only when its `ENVIRONMENT` is local or test. The token stays in the
tab's session storage, and `localTokenInterceptor` (`core/auth/local-sign-in.ts`) sends it with every
API call. Restarting the backend ends local sessions: sign in again.

Not in the backend yet, so these show an error against it: the KPI dashboard and the Admin overview
(`/v1/dashboard/summary`), rulesets (`/v1/rulesets`), the card assistant, and live updates (local
mode does not open the event stream). Use the demo mode for those.

the API. The account menu shows the environment ("Local, demo data"). Changes last until you reload

### Sign-in and sessions

The sign-in pages sit outside the shell, in `src/app/features/auth/`. `core/auth/auth.service.ts`
is the only code that calls MSAL.

| Page or event      | What happens                                                                                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`, signed out    | The UDAP landing page (`/udap/`, below). Its **Sign in** opens `/login`. A link to any other page goes straight to `/login`, and back to that page after sign-in.                                                               |
| `/login`           | **Sign in with Microsoft** starts the Entra redirect. MFA and conditional access apply at Microsoft; the portal never sees a password. Afterwards the user returns to the page they asked for (`returnUrl`, portal paths only). |
| `/logout`          | Opening it ends the session. With Entra ID it also signs out of Microsoft, which returns to this page to confirm. The account menu's **Sign out** goes here.                                                                    |
| `/auth/callback`   | Entra's redirect URI. MSAL finishes the sign-in and moves on to the page it started from.                                                                                                                                       |
| No activity        | After `auth.idleTimeoutMinutes` (default 30) without activity in any portal tab, a one-minute warning, then sign-out. Unsaved changes are not kept.                                                                             |
| API answers 401    | The session ends and the sign-in page says it has expired; signing in returns to the same page.                                                                                                                                 |
| Signed in, no role | The portal says the account has no access, and offers sign-out.                                                                                                                                                                 |

### UDAP landing page

`public/udap/` is the client-facing landing page: plain HTML, CSS and JS, outside Angular. The
portal serves it at `/udap/` (locally http://localhost:4200/udap/), and signed-out visitors to the
portal's own address land there (`authGuard`). The CSP applies, so the page has no inline `<style>`,
`<script>` or `style=""`: per-element values are classes in `udap.css`. The facts come from
AMC-SOL-01. `../udap-landing/index.html` is a self-contained copy to send as a file. After changing
the page, regenerate it with `python -I ../udap-landing/make_standalone.py`.

### Design system

- **Tokens:** `src/app/shared/theme/_tokens.scss` (Intertec palette, AA-checked text colours).
- **Global building blocks:** `_components.scss`, which covers panels, chips, alerts, tables and grid cells.
- **Shared components:** `src/app/shared/ui/`:
  - page header, KPI tile, empty state, problem alert, avatar and skeleton;
  - state, severity, SLA and card-type chips, and a confidence meter;
  - the `amcTime`, `amcMoney` and `amcLabel` pipes.
- **Shell:** `src/app/core/layout/`. It has role-filtered navigation, global search (Ctrl K), notifications from the live stream, the account menu, and the HK/EU time zone.

## Runtime configuration

`/assets/config.json` is read before bootstrap and mounted from a ConfigMap, so one image serves DEV,
NPR and PRD:

| Key                              | Meaning                                                                                                               |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `apiBaseUrl`                     | Platform API base (`/api`). MSAL attaches the token to every call under it and to nothing else.                       |
| `auth.tenantId`, `auth.clientId` | Entra tenant and the `amc-portal-spa` registration                                                                    |
| `auth.apiScope`                  | `api://amc-platform-api/.default`                                                                                     |
| `agGridLicenseKey`               | Empty in DEV (watermark). Set from a secret in NPR and PRD.                                                           |
| `auth.enabled`                   | `false` skips Entra sign-in in local work (mock users, or the backend's local sign-in); refused in NPR and PRD        |
| `auth.idleTimeoutMinutes`        | Minutes without activity before sign-out (default 30; `0` turns it off)                                               |
| `mockApi`                        | `true` answers the API from the in-browser mock (demo mode); refused in NPR and PRD; `npm run start:api` turns it off |

The dev proxy strips `/api` before forwarding (`proxy.conf.json`). The ingress must do the same, or
the backend must mount its routers under `/api`.

## API client

```bash
npm run api:snapshot    # backend venv active: writes openapi/openapi.json from the FastAPI app
npm run api:gen         # regenerates src/app/core/api/generated (never edit by hand)
npm run api:check       # CI drift check: fails if the committed client is stale
```

Call endpoints through the generated functions: `inject(Api).invoke(someOperation, params)`.
The backend currently exposes only `/health`, so the client grows as routers are implemented. Until
then the portal endpoints go through `core/api/portal-api.service.ts` (typed by
`core/api/portal.models.ts`), and `GET /v1/me` is called in `current-user.store.ts`.

## Container

`Dockerfile` builds `amc/portal-web`: unprivileged nginx on 8080 with `nginx.conf`. That file adds the
LLD security headers, SPA fallback, `no-store` on `index.html` and `config.json`, and one-year caching
for build files with a content hash in their names. Files from `public/` (the favicon, the logos) keep
their names, so browsers re-check them on each use (`no-cache`), and so does the landing page at
`/udap/`, which gets the same security headers as the portal. The CSP adds a per-request style
nonce, `img-src data:` and `frame-src https://login.microsoftonline.com` to the LLD policy. Angular,
AG Grid and MSAL need these to work under `default-src 'self'`.
